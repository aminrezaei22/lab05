=== PHASE 2: INVENTORY ===

Current shape: names is `const std::string names[]` in app/main.cpp;
scores is a jagged grid `double** scores` (num_students rows x
num_assignments columns). Student i is names[i] + scores[i][...] — nothing
but discipline keeps them together.

FUNCTION                   MODULE     USES          SCOPE
-------------------------  ---------  ------------  ------------------------
student_average            grading    scores        one student (by index)
assignment_average         grading    scores        whole roster
class_average              grading    scores        whole roster
find_extremes              grading    scores        one student (by index)
count_grade                grading    scores        whole roster
has_perfect_score          grading    scores        one student (by index)
is_at_risk                 grading    scores        one student (by index)
print_student_row          printing   name + scores one student (by index)
print_histogram            printing   scores        whole roster
print_assignment_summary   printing   scores        whole roster
print_roster               printing   names         whole roster

AFFECTED FUNCTIONS: 11  (7 in grading, 4 in printing)
Also affected:
  - print_header (printing): takes num_students/num_assignments but touches
    neither collection. Its parameters go away (see signature table).
  - app/main.cpp: builds both collections, frees the grid, and passes them
    to every call above.
  - tests/grading_tests.cpp: all 5 tests build a ScoreMatrix fixture
    → all 5 stop compiling.

JOINTS IN MAIN (the two collections indexed by the same variable):
  - case 1: print_student_row(names[row], scores, row, ...)
    names[row] and scores (row `row`) are matched only by the shared `row`.
  - scores[0]..scores[5] are filled by hand in the same order as names[]
    (the row numbers are hardcoded).
  - case 0: delete[] scores[student] loop (goes away entirely — no heap).

SIZE OF THURSDAY: 11 functions + print_header + main + 5 tests.


=== ARTIFACT 1 — PHASE 3: THE RECORD ===

STRUCT:             Student
MODELS:             One student: their full name and their score on each
                    assignment in the course.
LIVES IN:           include/student.h (new header)
                    Why: grading, printing, main, and the tests all need to
                    see Student. If it lived in grading.h, printing and main
                    would depend on the grading module just to know what a
                    student is. A small header with no dependencies of its own
                    (just <string>) can be included by everyone.
FIXED DIMENSION:    Number of assignments — constexpr int assignment_count{5};
                    defined in student.h. Every student takes the same
                    assignments, and it is a fact about the course, so it
                    belongs in the type as a fixed-size array.
VARYING DIMENSION:  Number of students on the roster. It changes between
                    classes (and tests need 0, 1, 2... students), so it is a
                    runtime int student_count that travels next to the
                    pointer to the first Student.

FIELDS:
  - std::string name;
  - double scores[assignment_count]{};

NOT FIELDS: average, letter grade, index/row number — those are computed or
describe what the program is doing, not the student.

COLLECTION PASSED AS:   const Student* students, int student_count
ONE STUDENT PASSED AS:  const Student& student

Sketch (for Thursday — not written yet):
    // include/student.h
    #ifndef STUDENT_H
    #define STUDENT_H
    #include <string>
    constexpr int assignment_count{5};
    struct Student {
        std::string name;
        double scores[assignment_count]{};
    };
    #endif


=== ARTIFACT 2 — PHASE 4: SIGNATURE TABLE ===

Legend:  [SAME PROMISE]  parameters change, what it returns/does does not
         [CONTRACT]      the contract itself changes
         [NARROWED]      was roster + index, now takes one Student

FUNCTION:           student_average
MODULE:             grading
OLD:                double student_average(const double* const* scores, const int student_index, const int num_assignments)
NEW:                double student_average(const Student& student)
PARAMETER REASONS:  student — const reference: reads one record, no copy of
                    the string, cannot modify it. Assignment count comes from
                    assignment_count, so it is no longer a parameter.
CONTRACT CHANGES:   [NARROWED] [CONTRACT] "student_index in range" precondition
                    is gone — there is no index to get wrong. Still returns
                    that student's mean.

---
FUNCTION:           assignment_average
MODULE:             grading
OLD:                double assignment_average(const double* const* scores, int assignment_index, const int num_students, const int num_assignments)
NEW:                double assignment_average(const Student* students, int student_count, int assignment_index)
PARAMETER REASONS:  students + student_count — walks the whole roster, so it
                    needs the pointer and how far it may walk.
                    assignment_index — which column to average; by value.
CONTRACT CHANGES:   [CONTRACT] Pre: assignment_index in [0, assignment_count).
                    Pre: student_count >= 0. New: student_count == 0 used to
                    be impossible (fixed roster); now it returns 0.0 instead
                    of dividing by zero.

---
FUNCTION:           class_average
MODULE:             grading
OLD:                double class_average(const double* const* scores, const int num_students, const int num_assignments)
NEW:                double class_average(const Student* students, int student_count)
PARAMETER REASONS:  whole roster → pointer + count.
CONTRACT CHANGES:   [CONTRACT] Empty roster (student_count == 0) returns 0.0.
                    (Decision: an empty class has no scores, and 0.0 keeps the
                    menu printable; the alternative was a precondition
                    student_count > 0. We chose 0.0 so it can be tested.)

=== ARTIFACT 3 — PHASE 5: CONVERSION ORDER ===

DEPENDENCIES (A --> B means A includes/uses B):

    student.h   (no dependencies)        utilities   (no dependencies)
        ^  ^  ^  ^                            ^   ^
        |  |  |  +---------- grading ---------+   |
        |  |  |                 ^                  |
        |  |  +---------- printing ---------------+
        |  |                    ^
        |  +------------- app/main (also uses grading)
        +---------------- tests  (use grading + utilities)

    utilities does not change at all.

BUILD FACT: the `library` target compiles grading.cpp AND printing.cpp
together, so the library does not build until both are converted.
`cmake --build build` builds every target, so it fails until main and the
tests are converted too.

ORDER:
  0. Add include/student.h (Student + assignment_count). Nothing uses it yet.
     → build GREEN, suite GREEN.
  1. grading.h / grading.cpp — all 7 functions.
     → RED (expected): printing.cpp, main.cpp and the tests still call old
       signatures.
  2. printing.h / printing.cpp — all 5 functions.
     → library builds: `cmake --build build --target library`
       Full build still RED (expected): main + tests.
  3. tests/grading_tests.cpp — replace ScoreMatrix with Student fixtures.
     → `cmake --build build --target grading_tests && ctest --test-dir build`
       SUITE GREEN again here. Full build still RED only because of main.
  4. app/main.cpp — const Student students[]{...}; student_count from
     std::size; remove new/delete; case 1 calls print_student_row(students[row]).
     → FULL BUILD GREEN, SUITE GREEN.
  5. Compare output:
       printf "1\n2\n3\n4\n5\n0\n" | ./build/gradebook | diff - docs/baseline-output.txt
     → must be identical EXCEPT Grace Hopper's row loses its "  !"
       (the is_at_risk bug — see contract note 4). Any other difference
       is a mistake.

TEST DECISION: tests go third — right after the library compiles, before
main. Converting them first would test functions that don't exist yet;
leaving them last would mean converting main blind. Putting them at step 3
means we have a green suite checking grading before we touch main.

HOW WE KNOW RED IS EXPECTED: after steps 1–2 every error should be a
"no matching function" / wrong-argument error in a file we have NOT converted
yet. An error inside a file we already converted is a real mistake.


=== ARTIFACT 4 — CONTRACT-CHANGE NOTES ===

1. Index preconditions removed: student_average, find_extremes,
   has_perfect_score, is_at_risk, print_student_row no longer take an index,
   so "student_index in [0, num_students)" no longer exists. The caller
   picks the student with students[i]; bounds are the caller's job.

2. Empty roster is now possible (student_count is a runtime value):
   - class_average(students, 0)          → returns 0.0 (our decision)
   - assignment_average(students, 0, i)  → returns 0.0 (same decision)
   - count_grade(students, 0, 'A')       → returns 0
   - print_roster / print_histogram / print_assignment_summary with 0
     → print their headings and nothing else (no crash).
   New tests to write Thursday: empty roster, one student, two students.

3. Fixed assignment count affects the tests: the current fixtures use 1, 3
   and 4 assignments. With assignment_count = 5 every fixture needs exactly
   5 scores and the expected values must be recalculated.
   DANGER: Student s{"X", {85.0}} compiles — the other 4 scores silently
   become 0.0 and the average becomes 17.0, not 85.0. Always write all 5.

4. Known bugs in the base code (found while reading, not fixed today):
   - grading.cpp:77  is_at_risk passes num_students as num_assignments.
     Disappears naturally with the new signature (no count parameter).
     This DOES change the output: the old code averages 6 values for a
     5-score student, so Grace Hopper (real avg 79.40, no score < 50) is
     wrongly flagged "!" in the baseline. After the refactor her "!" goes
     away. That one line is the only EXPECTED difference in step 5.
   - printing.cpp:12 print_header pads to num_students (6) instead of
     name_width (14) → "STUDEN" header. Plan: during the refactor keep the
     output identical to the baseline so the diff in step 5 is clean; fix
     it in a SEPARATE commit afterwards and regenerate the baseline.


=== SIGN-OFF QUESTIONS ===

Why is assignments fixed and students varying?
  Every student has the same assignments — that's part of what a student
  record is. Roster size changes by class and tests need 0/1/2 students,
  so it must be a runtime count.

Which modules see Student, and does its location follow?
  grading, printing, main, tests. None of them should depend on another
  module just for the type, so it gets its own header, student.h.

A function that should take one student instead of the roster?
  print_student_row — it took the name, the whole grid, an index, and both
  counts just to print one line. Taking const Student& removes the
  names[row]/scores[row] joint in main and makes the test fixture one student.

When is the suite red and how do we know it's expected?
  Red after steps 1 and 2; green after step 3. Expected errors are only in
  files not converted yet.

Hardest to convert?
  The test file: every fixture has the wrong number of assignments for a
  fixed size of 5, every expected value must be recalculated, and short
  brace lists compile silently with zeros.
